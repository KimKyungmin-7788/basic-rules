# 공통 규칙

- 사용자에게 보이는 글은 모두 한국어로 쓴다. 본문 답변뿐 아니라 작업 끝의 다음 단계 상자(요약·질문·버튼 문구),
  작업 목록, 진행 상황 한 줄 안내, 커밋 메시지, PR 제목·설명도 포함한다. 도구 결과나 시스템 안내가 영어여도 한국어로 답한다.
  코드, 명령어, 파일 경로, 고유명사는 원래 표기 그대로 둔다.
  긴 작업을 혼자 이어 가거나 대화가 요약된 뒤에도 한국어를 유지한다.

- 학생·학교에서 쓸 교육용 웹앱을 처음 배포하거나 배포 준비를 할 때는 `edu-app-launch` 스킬을 사용한다
  (보안 헤더, 개인정보처리방침·이용약관, 링크 미리보기, 학생 정보 유출 점검).

- 이미 배포한 교육용 앱에 외부 스크립트·글꼴·API나 저장·전송 기능을 새로 넣으면, 그 앱의 CSP와 개인정보처리방침을 함께 고친다.

- 생각을 나누거나 뭔가 전략 기획을 하거나 검색 같은 걸 할 때 답변 끝에 내가 모를 법한 새 개념을 두세 개씩 붙여줘

# 코딩 원칙

카파시가 지적한 AI 코딩 실수를 줄이기 위한 원칙이다. 오타 수정 같은 간단한 일에는 융통성 있게 적용한다.

- 먼저 생각하기: 애매하면 짐작하지 말고 묻는다. 해석이 여러 가지면 혼자 고르지 말고 보여 준다.
  더 간단한 방법이 있으면 말한다.
- 단순하게: 요청한 것만 가장 짧은 코드로 만든다. 한 번만 쓸 추상화, 요청하지 않은 설정 기능,
  일어날 수 없는 상황의 예외 처리는 넣지 않는다.
- 필요한 곳만 고치기: 요청과 관계없는 코드·주석·서식은 건드리지 않고, 기존 스타일을 따른다.
  관계없는 죽은 코드를 보면 지우지 말고 알려만 준다. 내 수정 때문에 안 쓰이게 된 것만 지운다.
- 목표부터 정하기: 시작 전에 "무엇이 되면 성공인지"를 정하고, 확인될 때까지 고치고 검증한다.
  여러 단계 작업은 단계마다 확인 방법을 붙여 계획을 짧게 말한다.

# 폰트
- 한글 폰트가 필요하면 학교안심 글꼴 키트(~/Documents/hakgyoansim-font-kit)에서 고른다.
- 쓰는 글꼴의 .otf 파일과 fonts/OFL.txt를 프로젝트의 public/fonts/ 에 함께 복사하고, hakgyoansim.css에서 그 글꼴의 @font-face만 가져온다.
- 폰트 파일은 형식 변환이나 글자 추리기로 수정하지 않고 원본을 쓴다.
- 키트 밖의 폰트를 쓰려면 먼저 라이선스를 확인하고 나에게 알린다.
